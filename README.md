# Hyperliquid 测试网交易终端

阿里云发布地址：`https://hyperliquid.sunshinedairy.net`。构建、发布与回滚操作见 [部署说明](docs/aliyun-deployment.md)。

这个项目把行情、委托和仓位管理放在一个页面里。打开页面就能查看测试网订单簿和 K 线；准备好有测试 USDC 的钱包后，可启用交易、挂单、撤单、开仓、减仓和平仓。

技术栈是 Next.js、React、TypeScript、Tailwind CSS、FameEX UI、KLineChart、TradingView Charting Library，以及社区维护的 `@nktkas/hyperliquid` SDK。市场包含默认永续、HIP-3 独立合约、现货和 HIP-4 预测。合约下单区支持限价、市价、止损市价/限价、止盈市价/限价、阶梯单、TWAP、追价和原生移动止损；限价可选 GTC、IOC、ALO。

布局以 [Hyperliquid 当前测试网交易页](https://app.hyperliquid-testnet.xyz/trade) 为参照：桌面左侧为市场信息和图表，中间为盘口，右侧为下单区；记录区位于左下，账户概览位于右下。平板和手机逐步改成两栏和纵向排列，桌面高度固定为一屏，订单输入和记录在各自面板内滚动；窄屏工作区可内部滚动，市场信息可横向滚动。基础组件、工具和图表继续复用本地 FameEX 源码，通过主题变量配置为深色与青绿色界面。源码来源和适配见 [packages/README.md](./packages/README.md)。

图表入口为“基础版”和“TradingView”。基础版仍使用 FameEX 的 `BaseKlineChart`，默认展示 MA 和独立成交量窗格。工具栏按 FameEX 展示分时、1分、5分、15分、30分、1时、4时、1日，其余周期放进下拉；完整范围为 Hyperliquid 支持的 1m、3m、5m、15m、30m、1h、2h、4h、8h、12h、1d、3d、1w、1M。“分时”使用交易所 1 分钟蜡烛的面积图，不生成秒级数据。

蜡烛类型、指标、重置和全屏图标来自 FameEX 原图标库。基础版支持 MA/VOL 显隐，TradingView 打开其原生指标面板。TradingView 的成交量不叠在价格图上，默认按 FameEX 成交量工具的约 25% 高度分层，剩余约 75% 留给价格图。成交量采用独立的柔和涨跌色，两套引擎均为 60% 不透明度（Alpha 0.6），不改变价格蜡烛的颜色。切换币种和周期只更新同一个 datafeed（图表数据接口）与订阅；两种引擎首次打开后保留实例，切换不重新加载页面。

从 TradingView 切回基础版时，保留当前币种和周期，恢复最新 K 线、默认每根 6px 间距、右侧 60px 留白和自动价格范围。隐藏图表时引擎会把宽度设为 0，因此先重新测量尺寸，等布局完成后再恢复视图；不能在零宽度下直接设置留白。

两套图表都读取 Hyperliquid 成交价 K 线，显示浏览器当前时区；交易所时间戳保持 UTC，不人为加减八小时。每次按 300 个周期的时间窗口读取历史，月线按自然月计算。TradingView 要求的 `countBack` 超过 300 时会连续补足多个窗口，并去重、排序；基础版向左拖动继续加载。无成交的周期不会伪造蜡烛，稀疏市场可能少于 300 根。查询范围限于最近 5000 个周期；API 本身保留最近 5000 根蜡烛。实时行情只补当前与前一根，避免重复下载整段历史。

以 BTC 5 分钟图离开两小时后返回为例：页面重新可见、网络恢复或 WebSocket 重连会触发一次共享历史校准，同时到达的实时蜡烛先缓冲。校准完成后，当前图表重载这份数据，再恢复视野和实时更新；即使查询期间进入了新的 5 分钟周期，新蜡烛也会保留。历史请求失败会进入自动重试，并提供“重试同步”入口；切换币种、周期或卸载页面后，旧恢复任务不能再更新当前图表。

“补齐共享历史”和“切换图表”分开处理。隐藏的图表保留实例；切回来时，已有连续数据就直接追平，需要重载时优先读取校准缓存，不会因为切换再次让另一套图表失效。同步期间连续点击会保留最后一次选择。缓存只覆盖已经读取的范围，基础版向左越过缓存边界时仍会查询更早历史；重载前的旧请求不能再次覆盖新数据。

**当前验证状态：真实行情、多钱包发现与连接已验证；订单和资金操作通过模拟交易所测试，不将模拟结果视为真实资金闭环验收。** 详细记录见 [VERIFICATION.md](./VERIFICATION.md)。这段经历暂未写入简历。

## 钱包、语言与实时更新

多个扩展同时安装时，页面优先接收 EIP-6963 的独立 provider（钱包通信对象），按钱包标识与对象去重。用户选中 MetaMask 后，连接、签名与事件监听始终绑定该对象，不再依赖可能被其他扩展覆盖的 `window.ethereum`。旧钱包仅作为兜底；即使全局注入属性读取抛错，也不阻断独立钱包发现。扩展自身的已知注入冲突不再被误报为应用交易错误，其他异常仍保留提示。

右上角可切换简体中文和英文，选择保存在当前浏览器。切换不跳转路由，当前币对、订单输入和钱包连接继续保留。标题与描述跟随币对、产品和语言更新，标题还包含最新成交价；行情过期后不再显示价格。标签由同一 React 组件管理，避免默认标签与动态标签重复。页面采用静态导出，不执行 JavaScript 的分享抓取器只能读取默认 BTC 元数据。

盘口同时订阅两路真实数据：`fast: true` 提供前 5 档，通常约每 0.5 秒更新；完整 20 档快照通常约每 5 秒更新。2026-11-02 的 22 秒只读采样分别收到 42 次和 5 次，间隔中位数约 526ms 和 5263ms。快速快照覆盖前档，旧报价在快速快照覆盖范围内会被移除；更深价格暂沿用完整快照，超过 15 秒丢弃。两路数据并不具有相同新鲜度，不能把合并后的所有深档当作同一时刻的完整订单簿。展示通过 requestAnimationFrame 合并，同一帧只绘制最新值，性能保护仍仅在持续高负载时降频。

仓位接收 `clearinghouseState` 账户推送，并保留 HTTP 定期核对。交易记录支持按方向和币种筛选，切换记录类型会重置筛选；不提供手动刷新按钮。表格展示方向、数量、仓位价值、开仓价、标记价、盈亏与收益率、清算价、保证金和累计资金费。点击“市价 / 限价”后，在 FameEX 弹窗选择数量或比例，预览时重新查询仓位；仓位已平、方向变化或数量超过剩余仓位时阻止提交。平仓始终使用 reduce-only（只允许减少仓位），仍需订单确认。

刷新页面自动恢复连接时保持静默，历史资金记录只展示在对应弹窗中；仅资金到账或划转确认产生成功通知，处理中和错误状态在当前资金弹窗显示。主动连接成功提示约 4.5 秒后关闭。桌面底部仓位与账户区占约 30% 高度且至少 260px，内部内容过长时在面板内滚动；账户区不再提供公开地址查询输入。标签页使用与页头一致的 H 图标。

## 启动

需要 Node.js 24 或更新版本、npm。浏览器验收使用本机 Google Chrome；普通查看行情不需要钱包。

```sh
cd /Users/julian/Documents/Codex/2026-11-02/hyperliquid-testnet-terminal
npm ci
npm run dev
```

打开 `http://127.0.0.1:3210`。正常情况下能看到 BTC 订单簿、5 分钟 K 线和“实时连接”。不需要 `.env`。HTTP 和 WebSocket 端点都在代码中固定为测试网，页面没有主网切换入口。

生产模式先停止开发服务器，再运行：

```sh
npm run build
npm start
```

币种菜单显示官方币种图标，并从图标左侧展开。自选保存在 `localStorage` 的 `hl-favorite-markets` 中；没有有效自选时可点击“一键自选主流币对”，只添加当前可用的主流合约，不自动覆盖已有收藏。

限价单支持点击买卖盘口填入价格。已选择比例时，按新价格与当前可下额度重算数量；手填数量会同步更新比例，空数量不会因点盘口自动增加。数量、金额单位和费用摘要使用同一草稿计算，调整这些输入不会自动下单。

## 连接钱包、准备资金，再下第一笔订单

以新钱包准备 10 USDC 测试资金、再买入 BTC 为例。点击“连接钱包”，页面通过 EIP-6963（浏览器钱包发现协议）列出已安装的扩展；只在你选中钱包后通过 `wallet_requestPermissions({ eth_accounts: {} })` 请求默认账户权限，由钱包扩展展示原生连接与权限窗口；同意后再用 `eth_accounts` 读取地址。每次主动重连都会请求原生权限，即使扩展此前已允许本站连接；刷新只读恢复不弹窗。只有钱包明确返回“不支持该接口”（4200 / -32601）才回退 `eth_requestAccounts`，拒绝、待确认及其他失败不会绕过权限。页面显示正在等待哪个钱包，未弹出时可打开工具栏中的扩展；取消后可重试，不会切链或发单。没有有效会话时，连接账户后会接着请求一次交易签名，由用户在钱包确认。权限项由钱包展示，前端不提供权限勾选；“保持连接”仅控制交易会话的本地保存方式。未安装扩展时，会提示用已安装 MetaMask、Rabby 等钱包的浏览器打开本页。页面没有私钥或助记词输入框。

连接后，右上角地址按钮打开“账户”，展示主账户地址、合约可提余额、现货可用余额和交易连接状态。“存款”“提款”保留资产与网络下拉；普通账户显示合约与现货间的划转入口，统一账户和组合保证金账户共享余额，不显示划转入口。各资金功能打开独立弹窗，不再通过钱包功能 Tab 切换。弹窗复用 FameEX Modal、Input、Select、Button；下单按钮按账户状态引导连接、存款或直接下单，不再设置独立的“启用交易”步骤。

首次使用时，页面先查询 Hyperliquid 的账户角色。若返回 `missing`，连接流程直接进入存款面板，不请求交易签名。必须先把测试 USDC 存入 Hyperliquid 并等待到账，再完成连接；Arbitrum Sepolia 钱包已有 USDC 不等于交易账户已经激活。已激活但当前余额为零的账户仍可授权。

### 准备测试资金

需要的是 **Hyperliquid 测试网账户里的 USDC**，不是钱包中任意网络的同名代币。页面提供两条入口：

- [Hyperliquid 测试网水龙头](https://app.hyperliquid-testnet.xyz/drip)：[官方说明](https://hyperliquid.gitbook.io/hyperliquid-docs/onboarding/testnet-faucet)要求同一地址已有主网充值历史，符合条件后可领取 1,000 mock USDC。刚创建的钱包不一定有资格，本项目不会代办主网充值。
- 本地 CCTP 充值：自行通过 [Circle 水龙头](https://faucet.circle.com/)准备 **Arbitrum Sepolia USDC**，并在该测试链准备 ETH 支付 Gas。CCTP 是 Circle 的跨链转移协议：在源链销毁 USDC，再在目标链铸造并转入 HyperCore 交易账户。没有测试币时，可继续查看真实行情和运行模拟验收。

例如源链钱包已有 20 USDC、ETH 为 0，还不能支付授权和存款的 Gas。先从 [Arbitrum 官方页面列出的测试水龙头](https://docs.arbitrum.io/chain-info)领取 Arbitrum Sepolia ETH，等待页面自动更新余额。页面会提示缺少测试 ETH 并禁用存款按钮；不需要为这个演示购买主网 ETH。

在“存款”填写 10 USDC，按以下顺序操作：

1. 点击切换到 Arbitrum Sepolia；钱包不认识该网络时，页面请求添加固定的测试网配置。
2. 点击“存款”，页面重新查询源链 USDC、ETH 和授权额度。额度不足时，先在钱包确认 ERC-20 `approve`，仅授权本次金额给固定 TokenMessenger 合约，不申请无限额度；已有足够额度则跳过授权。
3. 源链授权确认后，页面接着请求钱包确认存款，不用再次点击页面按钮。这一步调用 `depositForBurnWithHook`，目标固定为 HyperEVM 测试网，再由官方 Forwarder 转入**当前钱包地址的默认合约账户**。不是向任意地址发送 USDC，也不是直接 ERC-20 转账到 HyperEVM 钱包。
4. 源链确认后，页面显示“等待 Hyperliquid 到账”。只有源链哈希对应的跨链 nonce（请求编号）与主账户的 HyperCore 收款流水匹配，才显示“到账已核验”。余额增加本身不能作为这笔充值完成的证据。
5. 到账后关闭存款弹窗；已有会话可直接下单，尚未完成连接时通过下单区“完成钱包连接”继续签名。

当前实现单笔至少 5 USDC、小于 10,000,000 USDC、最多 6 位小数。跨链费用上限为 0.20 USDC，另付源链 Gas；新 HyperCore 账户还可能扣除 1 USDC 激活费。实际费用和到账金额以链上及交易所回报为准。合约地址与流程依据 [Hyperliquid USDC 说明](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/usdc)、[Circle CCTP 合约列表](https://developers.circle.com/cctp/references/contract-addresses)及 [Forwarder 数据格式](https://github.com/circlefin/hyperevm-circle-contracts/blob/master/src/messages/CctpForwarderHookData.sol)。旧 USDC Bridge 已标为弃用，因此未接入旧桥充值。

每笔请求先保存不含密钥的本地记录，再交给钱包。授权与存款都会重新估算源链 Gas，使用两倍当前基础费加优先费作为费用上限，为钱包确认期间的波动留出空间；实际收费以链上回执为准。拒签、费用过低或 Gas 余额不足的明确拒绝，会恢复金额输入和“存款”按钮。授权成功但取消存款后，再次点击会重新检查额度并跳过已有授权。切换钱包会停止下一步，不会继续替旧账户存款。

本地资金记录只展示进度，不锁住后续操作，也不提供人工解除限制。当前钱包请求处理中仍会禁用重复提交；每次新操作都重新查询余额、校验金额，并由钱包确认。源链有哈希或提款有 nonce 时，页面每 10 秒自动查询到账进度，关闭弹窗后继续查询；余额与提款费用每 15 秒自动更新。刷新页面不会重发资金请求，结果未知也不会自动重试。没有哈希的未知存款只能在钱包或链上记录中核对，不能仅凭超时判定失败。

### 一次建立交易连接，之后直接下单

假设钱包已经存入测试 USDC：在连接弹窗选中钱包后，页面先读取账户并核验已有交易会话。有有效会话就恢复；没有时，接着请求钱包签署一次无 Gas 的 `approveAgent` 消息，允许本应用的 `JulianTerminal` API 钱包代签下单、撤单和仓位调整。签名完成后关闭连接弹窗，直接填写价格、数量并下单。没有额外的“启用交易”按钮，也不会自动下单。拒签时保留只读账户，通过“重新连接并核验”重试。

MetaMask 的网站连接权限只允许读取账户和发起请求，本身不等于 API 钱包代签权限。[官方入门文档](https://hyperliquid.gitbook.io/hyperliquid-docs/onboarding/how-to-start-trading)仍区分连接与交易签名；这里把必要签名合并进连接流程，没有跳过签名校验。刷新只读恢复会话，绝不自动补签。

订单确认展示操作方向、带币种的数量、市价或明确的限价。确认按钮直接写“买入 / 做多”“卖出 / 做空”，只减仓则写“买入 / 平空”“卖出 / 平多”；现货与预测使用买入 / 卖出，仓位保护显示“确认止盈 / 止损”。弹窗只有一个交易按钮，取消走右上角关闭或 Esc。预估强平价当前显示 N/A，不拿已有仓位的旧强平价作为成交后估算。

订单确认可以勾选“不再显示此消息”，以后点击“下单”就提交；输入精度、余额、行情有效期和防重复提交校验仍然执行。平仓确认单独保存偏好。Header 右侧齿轮分别开启或关闭“下单确认”“平仓确认”，沿用 FameEX 的响应式存储方式：同页立即更新、跨页同步，刷新保留旧键值。关闭平仓确认后，仓位行的市价平仓和反手直接提交；限价平仓和移动止损仍需填写参数。撤单、停止 TWAP 直接执行，保证金模式与杠杆在各自弹窗确认一次后提交。所有提交仍以交易所回报为准，HTTP 成功不等于成交成功。

交易密钥由浏览器生成，默认保存在当前标签页的 `sessionStorage`，刷新后先查询交易所的 `extraAgents`，确认它仍属于当前账户且未过期，再恢复交易。勾选“保持连接”才保存到 `localStorage`；只在自己的设备使用。主钱包私钥不会被读取或保存。是否需要建立连接取决于本浏览器是否持有当前账户的交易密钥、对应 API 钱包是否仍登记且未过期，不看历史成交或账户余额是否为零。历史成交说明账户曾交易，但不能恢复丢失的交易密钥。当前应用与官方站点是不同来源，不能复用官方网页保存的密钥；即使交易所仍有登记，本地没有密钥时也需要重新签名建立连接。

不再人为限制一小时。交易所返回有效期时按该有效期处理；连接被撤销就回到待完成连接状态。查询失败时保留凭据并禁止下单，可在账户面板“重新连接并核验”，恢复到有效会话时不重复签名；失效时只有主动重连才请求新签名。主动断开或钱包断线会立即使内存会话失效，并把保存的会话标记为断开；刷新不会自动恢复。重新手动连接同一账户时，先展示钱包原生权限窗口，再查询 `extraAgents` 核验缓存，仍有效则复用，不重复 `approveAgent`。切换账户仍清除旧凭据，过期或撤销的代理也不会复用。断开后重新打开钱包选择弹窗；弹窗只显示可用扩展，使用 EIP-6963 提供的图标，不会自动选钱包或签名。交易所记录仍需在[官方 API 钱包页](https://app.hyperliquid-testnet.xyz/API)撤销。跨标签页签名序号通过 Web Locks 和本地单调计数协调，避免刷新或并发提交重复 nonce；浏览器不支持 Web Locks 或存储不可用时会阻止签名并提示。

USDC 的 ERC-20 授权只用于源链存款额度，不能代替交易连接。存款、划转、提款始终由主钱包签名，不使用 API 钱包。切换 EVM 网络不清除 HyperCore 连接，但源链存款前会单独核对 Arbitrum Sepolia。详情见[官方 API 钱包机制](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/nonces-and-api-wallets)。

### 仓位操作与逐仓保证金

例如持有 0.002 BTC 多仓：点“市价”可填写 0.001 BTC 部分平仓；点“限价”还能填写委托价格。这两类订单都只减仓。“反手”提交 0.004 BTC 卖出市价单，先平多，再开同等数量空仓，不使用只减仓；成交不足时可能未达到目标仓位。移动止损使用交易所原生请求，设置回撤比例或价差、可选激活价格，关闭页面后仍由交易所执行。

仓位止盈止损默认保护触发时的全部仓位，提交 `positionTpsl` 与 `s: "0"`，让交易所随仓位数量变化处理。开启“配置金额”后改为固定数量；开启“限价保护”后还需填写触发后的委托价格。下单区和仓位弹窗共用价格/收益联动：百分比是杠杆收益率（ROE），USDC 是所选数量的预计盈亏，不含手续费和资金费。输入一侧会更新另一侧；价格、方向、杠杆或数量改变后也重新计算。旧保护单不会自动替换，需在当前委托核对并撤销，避免重复。

逐仓仓位的保证金金额可以点击，弹窗支持追加和移除。提交前重新查询账户类型、余额和仓位；全仓不显示此入口。移除后至少保留初始保证金和仓位名义价值 10% 中较大的一项，严格逐仓市场不能手动移除。金额最多两位小数，接口按带正负号的百万分之一单位提交，最终仍以交易所校验为准。网络结果不明时保留待核对状态，禁止自动重发。

上述操作只确认一次。提交前再次核对当前钱包、仓位数量和方向；切换钱包会关闭旧弹窗。价格、保证金、资金费、订单参数等标签支持鼠标悬浮和键盘聚焦说明。新增路径使用模拟交易所覆盖请求与失败分支，尚未执行真实账户签名验收。

### 现货资金与下单

默认账户的现货、预测交易使用现货账户资产。若 10 USDC 已进入默认合约账户，打开“划转”，核对“从合约账户到现货账户”（右侧按钮可交换方向），输入金额并由主钱包签名 `usdClassTransfer`。发送前重新查询余额，不得超过合约可提余额；反向划转使用现货总额减冻结额。统一账户或组合保证金账户不使用这套独立划转，页面会引导至官方管理；HIP-3 独立保证金账户与其他跨链路线保留官方入口。划转卡片、交换方向和金额“最大值”参考 FameEX 的 Transfer/ModeSelect、QuantityFormItem，基础组件继续使用本地 `@fameex/ui`。

### 提款回当前钱包

账户区提供“存款 / 划转 / 提款”。没有连接钱包时，先选择扩展，连接后继续刚才选中的资金操作。资金操作始终由主钱包签名；即使交易签名取消，仍可从账户面板进入资金功能。

例如从合约提取 10 USDC：打开“提款”，页面先查询可提余额、HyperEVM Gas 和账户激活费，在同一页展示网络、收款地址和费用。输入 10 后预计到账 9.8 USDC；0.2 USDC 跨链费从提款金额扣除，Gas 和可能发生的激活费另行预留。若现货可用 HYPE 足够，Gas 用 HYPE 支付，否则按最新 HYPE 价格预留 USDC。“最大值”只填写扣除预留费用后的可提金额，不发起签名。

核对后点击“提现至 Arbitrum Sepolia”。`use-funding` 再查余额和费用；费用上升时留在当前页更新报价，必须再次点击才能请求签名。SDK 用主钱包签署 `sendToEvmWithData`，网络固定为 Testnet，CCTP 目标域固定为 3（Arbitrum），不是 EVM 链 ID 421614。普通账户使用合约可提余额，现货 USDC 可通过“现货转入合约”打开预置方向的划转弹窗；统一账户自动使用维护保证金限制后的共享现货余额。收款地址固定为当前钱包，不支持外部地址提款。

请求接受后显示“等待跨链到账”。页面按持久化的 nonce 查询 Across 测试网索引，再检查 Arbitrum Sepolia 回执中的 USDC Transfer：币种、收款人和足额金额都匹配，才显示“到账已核验”。响应丢失时保留未知记录，刷新后继续查询，禁止重复提交；拒签或明确的交易所拒绝可重新操作。关闭弹窗不会撤回已发出的请求。

本地存提仍只提供 USDC 的 Arbitrum Sepolia CCTP 通道；官方其他资产、旧桥和 HyperEVM 等路线未在本地接入。提款金额为 0.4 至 10,000,000 USDC、最多 6 位小数。官方 UI 和请求字段核对来源为 [测试网交易页](https://app.hyperliquid-testnet.xyz/trade)及 [Send to EVM with data 文档](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/exchange-endpoint#send-to-evm-with-data)。真实钱包签名和跨链到账仍需账户持有人逐笔验收，不能把模拟测试结果写成生产交易经历。

## 一次完整下单如何走通

接着输入限价和 BTC 数量。比如价格是 70,000、数量是 0.0003，名义金额就是 21 USDC。这个数字仅用于理解输入，实际测试请以当时盘口为准，并在确认框检查方向、数量、价格和账户。项目用十进制运算处理金额，不会静默截断超精度数量。

点击“下单”生成待确认参数；在订单弹窗点击“买入 / 做多”等对应方向按钮，才让当前交易连接签名，并向测试网 `/exchange` 发送一次请求。交易所回报为挂单时，订单进入“当前委托”；点击该行“撤单”直接发起撤单，成功后从列表消失。

切到市价单时，项目取买一或卖一作为参考价，设置 0.5% 滑点边界，以 IOC 订单提交。IOC 表示立即成交可成交的部分，剩余部分取消，并不保证全部成交。仓位列表显示带方向的数量、开仓均价、未实现盈亏、保证金和交易所返回的预估清算价。在“市价”或“限价”平仓弹窗填写小于当前仓位的数量可部分减仓；填写剩余数量可平仓。这两类请求强制携带 `reduceOnly`，避免平仓反向开出新仓。

下单区顶部的“保证金模式”和“杠杆”分别打开设置弹层。连接账户后，按钮读取 Hyperliquid `activeAssetData` 的已生效设置；弹层修改的是草稿，取消不会写入。点击弹窗确认后，先检查整数杠杆与该市场上限、是否仅允许逐仓，再提交一次请求。交易所接受 `updateLeverage` 后重新读取设置；拒绝时保留原值。界面展示资金费率；资金费率结算、撮合和清算由 Hyperliquid 完成，前端读取结果并管理交互状态。

## 行情、盘口与性能

顶部市场栏读取实时 `activeAssetCtx`，展示标记价、预言机价、24 小时涨跌、成交额、按标记价折算的持仓量，以及每小时结算的资金费率倒计时。这里的倒计时是本机时钟到下一个整点，并不是已扣款回执。

订单簿按“价格 / 数量 / 累计数量”展示。先按最优报价排序，再从买一、卖一向外累计；卖盘反向显示，使最优卖价贴近中间价差。显示档数随面板高度调整，接口返回的真实档位不足时保持行高并贴近价差，不补造价格。悬停或键盘聚焦某档，左侧浮层展示该价格距盘口中间价的距离、从最优价累计到该档的加权均价、币数量和 USDC 金额。鼠标不动而盘口变化时，也会重新命中鼠标下的档位。累计遮罩只覆盖当前一侧的最优价到悬停档；卖盘虚线在该档上沿，买盘虚线在下沿。

“最新成交”先读历史，再合并 WebSocket 推送，按成交 ID 去重并按时间倒序保留最近 100 笔。末尾的链接使用交易所返回的非零交易哈希，在新窗口打开官方测试网浏览器；不会根据成交 ID 猜测交易链接。

行情没有固定的 200ms/500ms 节流。每类数据通过 `requestAnimationFrame` 在下一帧提交：盘口只保留最新快照，蜡烛按时间合并，成交按 ID 合并。单次突发数据不会触发降级；只有持续掉帧、长任务、模块同步耗时偏高或堆内存压力时，才退到 30/10fps，并在连续健康窗口后逐级恢复。后台页不会因浏览器暂停动画帧而被判定为卡顿。

页脚“性能”可查看每个模块的输入/更新速率、同步耗时、待处理数、缓存数、合并/丢弃量及数据年龄，支持导出不含账户信息的 JSON。样本窗口和数据缓冲均有上限；React 生产 profiling 已开启。同步耗时不包含全部 GPU 绘制，浏览器提供的堆内存是整页估计，不能仅凭它认定某模块泄漏。

## 市场下拉与不同下单区

点击币种展开 FameEX SmartPopover，搜索框、分类 Tab、收藏和价格/涨跌/成交额排序共用现有组件。列表只渲染可见行及少量缓冲；切币只修改状态，不刷新页面。所有、自选、合约、现货、预测、HIP-3、HIP-4 对应真实市场；HIP-3 是独立部署合约，HIP-4 是预测协议分类，与“预测”指向同一组市场。没有可靠资产分类字段的市场不凭名称硬分为加密货币或传统金融。

市场名称只用于展示，请求仍使用交易所的原始代码。例如 HYPE 现货可能使用 `@1035`，预测使用 `#<encoding>`；请求中的资产 ID 分别按现货交易对索引、HIP-3 DEX 索引及 outcome/side 编码构造，不能拿 token 索引或显示名替代。[官方资产编码规则](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/asset-ids)与[价格/数量精度](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/tick-and-lot-size)是这部分校验依据。

切到现货时，下单区变为买入/卖出、限价/市价、GTC/IOC/ALO 和余额比例，不显示合约杠杆或只减仓。余额取自 `spotClearinghouseState`，可用量为总量减冻结量；预览和最终确认都会重读余额及账户费率，卖单不得超过持有量，买单按整笔订单预留手续费。切到预测时，展示事件规则与两个结果，可切换结果份额；数量为整数，报价在 0.00001–0.99999 之间。预测卖出使用已有份额，不能按永续做空。现货另支持阶梯、TWAP 和追价；预测另支持阶梯单。每个产品仅显示当前官方交易页支持的订单类型，条件单、附带 TP/SL 和移动止损仍只用于合约。

HIP-3 的保证金、仓位和委托按对应 DEX 查询，不混用默认永续账户。扩展市场元数据每五分钟更新，默认合约摘要每三十秒更新；当前选中市场行情仍由 WebSocket 实时驱动。元数据没有提供的 HIP-3/预测统计显示为 `—`，不会补造价格或涨跌。已实现默认合约与现货 USDC 划转；HIP-3 资金调拨、预测份额合并/赎回与组合保证金借贷不属于已实现范围。

## 高级订单怎样执行

“限价单 / 市价单 / 专业”相邻排列。专业菜单复用 FameEX 的 Dropdown 样式与原箭头，悬停入口没有背景色，选中高级类型后原位显示名称。菜单支持键盘选择、Esc 关闭和窄屏边界限制；合约、现货和预测共用这一个选择器，类型由产品能力过滤。

下单数量可以按币或 USDC 输入，也可用 FameEX Slider 选择最大可下数量的比例。最大可下与可用保证金来自账户接口，只减仓上限来自当前仓位；手续费使用账户实际 maker/taker 费率。金额、初始保证金和手续费是估算，条件单触发后的真实成交仍以交易所回报为准。

- 条件单：填写标记价格的触发条件，支持触发后市价或限价。父单附带 TP/SL 使用 `normalTpsl` 分组；仓位区可按最新查询到的仓位数量新增只减仓保护单，使用 `positionTpsl`。不会静默覆盖已有保护单，既有订单可在当前委托撤销。
- 阶梯单：在价格区间内分配 2–50 档，支持平均、递增、递减数量。总数量守恒，每档独立检查最小金额和精度；现货/合约每档至少 10 USDC，预测每档至少 1 USDC。批量回报逐笔显示，部分拒绝不会报告为全部成功。
- TWAP：总金额至少 100 USDC，5–10080 分钟，可随机执行、指定触发条件及最高买入/最低卖出价格。价格边界必须在触发价（无触发价时为当前标记价）的外侧。交易所持续执行，关闭页面不会停止；“TWAP”列表可查看已执行量并确认撤销。最高/最低价格映射为 `details.s`，已对照官方当前网页的请求构造及校验逻辑确认；当前 SDK 对该字段的注释滞后，页面使用官网语义。
- 移动止损：调用原生 `trailingStop`，由交易所跟踪标记价的有利极值并在回撤达到距离或比例时触发，支持激活价格和只减仓。使用返回的订单 ID 在当前委托核对/撤销。
- 追价：确认框明确授权当前页面在总数量和价格上限/下限内持续提交 ALO 委托，最多 5 笔。每次改价先确认撤销并读取最终剩余数量，再重挂，避免部分成交导致超量。不会追逐自己的最优报价。页面关闭、会话变化、过期盘口或不明回报都会停止改价；已挂订单仍可能成交，需在当前委托撤销。策略列表的“停止改价”只停止后续自动动作。

例如买入 6 HYPE，价格区间 18–22 USDC、平均分成三档：预览生成 18、20、22 三个价格，每档 2 HYPE，总金额 120 USDC。现货模块把整批金额加预估手续费与可用 USDC 比较；确认前再次查询，若余额已被冻结则阻止提交。只有确认后才发送一个包含三档的请求。某一档被拒绝时，其他已接受档位仍保留，不会自动重发整批。撤单在当前委托中逐笔确认，资产索引仍使用该现货交易对的编码。

现货追价沿用相同的撤单/剩余量流程，并在每次重挂前重新查余额，余额不足就停止改价。现货 TWAP 设置最高买入价时按该边界估算预算；未设置时按当前价与触发价较高者加 3% 估算，后续涨价或其他订单占用余额仍可能使 TWAP 无法全部完成。预测只使用已有份额，不提供官方当前未开放的 TWAP、追价或条件单；份额合并/赎回是单独资产操作，本项目未实现。能力边界参考[当前测试网交易页](https://app.hyperliquid-testnet.xyz/trade)和[HIP-4 说明](https://hyperliquid.gitbook.io/hyperliquid-docs/hyperliquid-improvement-proposals-hips/hip-4-outcome-markets)。

SDK 0.33.3 尚未暴露原生移动止损，TWAP 时长校验也仍停留在一天；本项目沿用该 SDK 的签名与传输，按[官方交易接口](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/exchange-endpoint)构造原生动作，并按[订单类型说明](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/order-types)限制最长七天。模拟验收会恢复签名地址并检查请求，但真实测试网接受情况仍需要有余额的账户验收。

## 请求失败时如何处理

HTTP 请求成功并不一定代表下单成功。程序检查返回的每笔订单状态，把拒单、挂单、部分成交、全部成交分别展示；余额不足等错误会显示交易所回报。

请求发出但回报丢失时，订单可能已经成立。页面不会自动重发，而是保留随机生成的客户端订单号 `cloid`，暂停新的下单。点击“查询未确认订单”会向 `/info` 查询该订单。批量单保存并逐一查询全部 `cloid`。记录按公开地址保存在本地，刷新后重新连接同一地址仍能核对。只有查到明确状态，或签名已过期超过 30 秒且查询仍返回不存在，才解除这笔待确认状态。

原生 TWAP/移动止损不接受客户端订单号。回报丢失时，本地编号只用来标记未确认请求，不冒充链上订单号查询。需在官方页和本地委托/TWAP列表核对，签名过期至少 30 秒后勾选核对声明，才能手动解除本地重复提交保护；这不代表订单成功或失败。

钱包拒绝建立连接会回到待完成连接状态，不发交易请求。切换账户或断开钱包会使当前会话失效并关闭预览；切换 EVM 网络保留交易授权，充值前单独核对测试链。订单簿过期 15 秒后暂停下单；账户数据过期 30 秒或查询失败也会暂停交易。取消操作不会撤销已经发送并被交易所接受的订单，仍需查询委托和仓位。

## 可复现验证

以下命令均在项目根目录执行。前四项检查源码和核心计算；浏览器模拟测试拦截钱包及交易所请求，不会发送真实订单。

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e -- --workers=1
```

下面两项访问真实测试网，只查询行情。`verify:read` 校验市场配置、HTTP 订单簿、历史 K 线和 WebSocket 推送；`test:live` 检查真实页面、BTC/ETH 切换和手机排版，并断言没有 `/exchange` 请求。

```sh
npm run verify:read
npm run test:live
```

准备好公开地址后，也可只读检查余额、委托和仓位：

```sh
npm run verify:read -- 0x替换为你的40位十六进制公开地址
```

原始行情回执位于 `output-tdd/hyperliquid/read-only.json`，浏览器结果位于 `output-tdd/playwright/hyperliquid/`，本轮截图位于 `output-tdd/playwright/web3-onboarding/`。这些本地验收文件通过 `.git/info/exclude` 排除，没有加入源码提交。`npm ci` 会安装 Husky；pre-commit 对暂存文件运行 Biome，再做类型检查和单元测试。

## 有测试余额后补齐真实验收

这些步骤会实际改变测试网账户状态，由账户持有人逐笔确认。先按上文完成测试网充值，记录源链哈希、HyperCore 收款流水和实际到账金额；若要验证现货，再划转一笔小额 USDC 并核对两侧余额：

1. 授权测试网交易会话；记录公开地址和实际余额。
2. 选择 BTC，在当前买一以下设置买入限价，数量满足至少 10 USDC 名义金额；确认出现挂单订单号，再撤销并确认当前委托已移除。若行情变化导致成交，先按仓位处理，再重新做挂单撤单验收。
3. 使用满足最小金额的一笔小额测试市价单开仓，检查成交记录和仓位数量。
4. 减少一部分仓位，确认剩余数量；再平掉剩余仓位，确认没有本次新增持仓或遗留委托。
5. 在当前委托、成交记录和操作记录核对结果；操作记录仅保留在当前页面内存，刷新后清空。

随后用官方测试网页面或 `/info` 再核对订单状态、成交和最终仓位。只有这一步确实通过，才把项目以“个人 Hyperliquid 测试网项目”写入简历，并描述实际完成的模块与验收结果。不能据此声称生产环境交易经验、量化收益或清算引擎研发经验。

## 对照源码理解状态变化

- `src/lib/hyperliquid.ts`：固定测试网连接、读取主账户数据、钱包连接和可恢复交易会话。浏览器扩展签交易授权及资金划转，订单使用已登记 API 钱包的 L1 签名，避免混淆两种协议；参见 [官方签名说明](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/signing)。
- `src/lib/funding.ts`：固定测试链和 CCTP 合约、校验 USDC 金额、模拟合约调用、提交源链授权/充值，构造 CCTP 提款参数、预留 Gas/激活费，并匹配跨链到账证据。
- `src/hooks/use-wallet-providers.ts`、`use-funding.ts`：分别负责扩展发现，以及余额、待确认资金记录和轮询；`src/components/trading/web3-dialog.tsx` 与 `withdrawal-form.tsx` 渲染账户、存款、划转、提款及确认页，资金请求和记录由 hook 管理。
- `src/lib/use-market.ts`：订阅订单簿和 K 线；重连后补 HTTP 快照，旧市场的异步结果不能写回新市场。订单簿消息按完整快照处理；K 线按时间去重合并。
- `src/lib/orders.ts`：数量精度、价格有效数字、10 USDC 开仓门槛、IOC 滑点边界和回报解析。资产编号来自元数据索引，不把主网 BTC 编号搬到测试网；参见 [价格与数量精度规则](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/tick-and-lot-size)。
- `src/lib/chart-feed.ts`：把 Hyperliquid 毫秒 OHLCV 转换为两种图表契约，校验币种、周期、价格范围，处理历史翻页、推送先到和退订。遵循 [Hyperliquid K 线接口](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/info-endpoint#candle-snapshot)、[KLineChart 数据接入](https://klinecharts.com/en-US/guide/data-integration) 和 [TradingView Datafeed](https://www.tradingview.com/charting-library-docs/latest/connecting_data/datafeed-api/) 的时间及异步回调规则。
- `src/hooks/use-terminal.ts`：协调钱包、账户、预览确认、回报核对及刷新；`use-order-form.ts` 管理输入草稿，`use-margin-settings.ts` 管理保证金与杠杆弹层。
- `src/components/trading/order-type-selector.tsx`、`order-options.tsx`：共用的类型菜单和高级参数 UI；现货/预测的状态与校验在 `use-cash-order-form.ts`、`cash-order.ts` 中。
- `src/lib/order-ticket.ts`、`submit-ticket.ts`、`native-orders.ts`：构建与提交条件单、阶梯单和原生高级订单，逐笔处理回报；`use-chase-orders.ts` 管理浏览器追价的生命周期。
- `src/lib/performance.ts`、`frame-batch.ts`：采样模块指标与逐帧提交，只有持续压力才降级。
- `src/lib/trading.ts`：提交交易动作、校验杠杆、保存未确认订单的业务规则。UI 不直接拼签名请求。
- `src/hooks/use-chart-feed.ts`、`use-tradingview.ts`、`use-chart-controls.ts`：分别处理共享数据、TradingView 生命周期和工具栏操作。旧市场的迟到回调会结束，但不能写入新市场。
- `src/components/terminal.tsx`：只负责页面布局；`src/components/trading/` 渲染市场、盘口、账户、记录和弹层。
- `tests/terminal.spec.ts`：通过页面验证上述流程，只有外部钱包和网络边界被模拟。

行情元数据每 30 秒刷新，账户每 15 秒轮询，并由订单更新、成交推送触发刷新。公开最新成交最多展示 100 条，账户成交最多展示 30 条，页面操作记录最多保留 100 条。它适合演示和学习交易产品研发；长时间压力、真实浏览器钱包兼容性和真实交易行为仍需要后续账户验收。

## 基础版 K 线操作

左侧工具栏可从侧边箭头收起、展开，也可画线、磁吸、锁定、隐藏或清除绘图；绘图按币种保存在当前浏览器。上方“指标”提供与 FameEX 相同的 27 个指标，并可恢复 MA/VOL。“交易线”分别控制持仓、委托和止盈止损的显示。“重置图表”会清除当前市场的绘图及额外指标，删除对应本地绘图数据，恢复初始化时的 MA/VOL、成交量窗格比例、默认蜡烛间距、价格轴和最新行情位置。TradingView 重置后同样恢复初始成交量窗格。绘图栏仅通过左侧箭头收起、展开。

连接账户后，持仓线显示开仓均价、数量与盈亏。悬停可平仓或设置止盈止损；拖动止盈止损控件会把价格带入确认框，确认后才提交。已有整仓保护线可拖动修改原单，订单线的关闭按钮可撤单。部分仓位与重复保护单保持为独立订单线。切换市场或账户时旧线条自动清理；取消弹窗会恢复账户当前价格。键盘 Tab 也可进入图表平仓、保护和撤单入口。

图表只负责价格交互。提交仍经过最新仓位、订单状态、价格精度和只减仓校验；数量、方向或订单在确认期间发生变化时停止提交。实现和源文件适配见 `packages/README.md`。
